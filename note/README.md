# note

노트 서비스. 화면은 author_manager · reference_manager와 같은 **RACK** 표이고,
저장은 그 둘과 다르다 — **노트 하나가 파일 하나**다.

```
data/note/projects/<프로젝트>/
    notes/2026-10-08-노트-서비스-설계.md      ← 노트
    templates/회의록.md                        ← 템플릿 (만들 때 복사된다)
```

이 폴더를 **Obsidian에서 그대로 열 수 있다.** 여기엔 우리만의 형식이 없다 —
머리말은 YAML, 본문은 마크다운, 할 일은 GFM 체크박스다.

## 노트 한 장

```markdown
---
title: 노트 서비스 설계
date: 2026-10-08
tags: [노트, RACK]
place: IRIS          # 모르는 키도 그대로 보관된다
---

본문. `- [ ] 할 일`은 todos 탭에 모인다.
```

**속성 추가**는 스키마가 없어서 가능하다. `title · date · tags` 말고 머리말에
있는 키는 전부 편집기에 그대로 나오고, 저장할 때 되돌아간다.

## 탭

| 탭 | 무엇 |
|---|---|
| notes | 전체 목록 — date · title · tags · 할 일 수 · words · 첫 줄 |
| todos | **모든 노트의 체크박스를 모아서** 한 줄씩. 여기서 체크하면 그 노트의 그 줄이 바뀐다 |
| tags | 쓰이는 태그와 개수. 누르면 그 태그의 노트 탭이 열린다 |

할 일은 **모으기만 하고 저장하지 않는다.** 노트의 그 줄이 유일한 사본이라, 두
곳이 어긋날 수가 없다. 체크할 때는 그 줄이 *여전히 그 할 일인지* 확인하고 쓴다
— 다른 곳에서 편집돼 줄이 밀렸으면 409로 거절하고 다시 읽으라고 한다.

## 검색

검색창은 제목·날짜·태그·첫 줄을 바로 거르고, 두 글자가 넘으면 **본문도**
서버에 물어본다(`/api/search`). 본문에서 걸린 노트는 `첫 줄` 칸에 **걸린 줄**을
대신 보여준다. 목록이 본문을 들고 있지 않기 때문이다 — 노트가 길어도 목록
응답은 작게 유지된다.

## PDF

고른 노트들을 **브라우저의 인쇄**로 넘긴다 (`?print=<id>,<id>`). 포털 프레임이
아니라 **새 탭**으로 열어서, 인쇄되는 게 포털이 아니라 노트가 되게 한다.

PDF 라이브러리를 쓰지 않는 이유는 한글이다. jsPDF로 글자를 쓰려면 CJK 폰트를
5~15MB 박아야 하는데, 브라우저 인쇄는 시스템 폰트를 그대로 쓴다. 인쇄 스타일은
A4 한 장에 노트 하나, 제목이 쪽 끝에 혼자 남지 않게 한다.

## 저장 충돌

노트는 파일의 mtime을 `version`으로 들고 다닌다. 저장할 때 자기가 읽은
`baseVersion`을 보내고, 그 사이 파일이 바뀌었으면 409 + 최신 내용을 돌려받는다.

> `version`은 **문자열**이다. `st_mtime_ns`는 1.8e18이라 JavaScript의 안전 정수
> 범위를 넘고, 숫자로 주면 클라이언트가 반올림해서 돌려줘 **모든 저장이 충돌로
> 보인다.** (실제로 그렇게 한 번 만들었다가 고쳤다.)

## 손으로 확인할 때

포털을 통해서만 동작한다 (프로젝트 경로에서 `PORTAL_PROJECT`를 읽는다).
임시 포털에 서비스를 걸어서 보는 방법은 `service_manager/DEPLOYMENT.md` 참고.

```bash
cd ~/web_service/note
LILAK_UI_PATH=~/web_service/lilak_ui npx vite build
```

## 아직 없는 것

  줄은 견딘다)
- `[[위키링크]]`와 백링크 (reference_manager의 인용 연결과 같은 구조로 가능)
- 첨부파일, 그래프 뷰, 플러그인
