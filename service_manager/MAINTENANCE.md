- 고치기 전후로 `~/web_service/scripts/test-all.sh`를 돌린다. 전부 통과해야 커밋한다.
- 버그를 고치면 그 버그를 잡는 테스트를 하나 남긴다.
  - 포털: `service_manager/tests/test_security.py`
  - rack 저장소: `lilak_portal_auth/test_store_*.py`
  - UI 키트: `lilak_ui/src/__tests__/`
- `lilak_portal_auth`를 고친 뒤에는 rack 서비스(note, author, reference, academic, asset)를 재시작해야 반영된다. 설정 → 시스템 → "실행 중인 서비스 모두 재시작" 버튼으로 한 번에.

### 남은 것
- [ ] **포털 토큰을 화면 스크립트가 못 읽게**: 지금은 localStorage와 JS 쿠키에 있어서, 어느 서비스든 XSS가 하나 생기면 토큰이 털린다. 서버가 HttpOnly 쿠키를 굽게 바꾸고 서비스 iframe에 `sandbox`를 붙인다. 장기적으로는 서비스마다 다른 주소(서브도메인).
- [ ] **서비스마다 따로 서명키**: 지금은 모든 서비스가 같은 HS256 비밀키를 알아서, 서비스 하나가 털리면 매니저 토큰을 만들 수 있다. RS256(포털만 개인키)이나 서비스별 `aud`로.
- [ ] 서비스에 포털 환경변수 전체(`PORTAL_SECRET_KEY`, `RESEND_API_KEY`)를 넘기지 말고 필요한 것만 (`adapters/managed.py`)
- [ ] 연간 재인증(`POST /api/account/verify`)이 본인 확인 없이 도장만 찍음. 메일 코드 왕복으로
- [ ] 동기화는 `https://`만 허용, 동기화 토큰을 평문 JSON 말고 해시로 보관
- [ ] 페어링 요청 큐(20칸)를 아무나 채울 수 있음. IP당 제한
- [ ] 이메일이 DB에서 unique가 아님(서비스가 이메일로 계정을 잇는데)
- [ ] `/api/auth/refresh`로 토큰을 무한 연장 가능. 최대 수명(예: 30일) 두기
- [ ] rack 서비스 밖의 서비스(analysis, nptoy, stark_planner)는 자체 `portal_auth.py` 복사본을 씀. 같은 검사가 들어갔는지 확인

## 장기 방향

- **직접 계속 만들 것**: elog, 장비 모니터, author·reference·activity·note 같은 연구실 앱, RACK 디자인과 UI 키트, 동기화·핸드셰이크
- **기성품으로 바꿀 것 검토**
  - 로그인: Authentik/Keycloak(2단계 인증, 학교 계정)
  - 서비스 실행·연결·HTTPS: Docker Compose + Traefik
  - 백업: restic
- rack 서비스가 수만 건을 넘으면 `Document`를 SQLite로 바꿀 것(저장소 경계가 이미 한 곳이라 교체가 쉬움)
